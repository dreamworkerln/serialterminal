# ST: ревизия таймаутов и интервалов

Ревизия production Python: `src/`, entrypoints и `tools/`. Тестовые mock deadlines не являются runtime настройками. Начальный AST список: 114 строк; hotkey `self.retry="?"` исключён как ложное совпадение. Дополнены TTL, вложенные poll waits, CLI defaults, sweep phase returns и новые профильные формулы. JSON с контекстом и исходный dirty snapshot хранятся в журнале `ST_TIMING_REVISION_20261012T131217Z`. Строки первоначального списка относятся к BASE; дополненные — к текущим исходникам. Дубликаты применения одной policy оставлены для проверки всех мест.

Физические deadlines принадлежат ChatterProfile. Generic FT1 получает optional `timing_budget_s(control/resume/drain)` и не импортирует LoRa. Профиль читает `/config` и реальные SPI registers через `/radio read config`; cache привязан к connection generation, controller epoch и configuration revision. При local boot последний проверенный PHY оценивает control/idle deadline уже принятого файла, но не даёт RF admission: новая отправка требует READY и fresh readback. После SAVED/repair старый PHY не используется даже для boot deadline. Нет достоверного readback — нет RF submission, ошибка `radio_timing_unavailable`. Явные caller deadlines сохраняются.

Расчёт следует SX127x/RadioLib и существующей firmware retry policy; исходники прошивки в этой задаче не менялись. Tss = 2^SF / BW; LDRO берётся из readback, CR — знаменатель 5..8. Payload symbols = 8 + max(ceil((8PL − 4SF + 28 + 16CRC − 20IH)/(4(SF − 2DE))) × CR, 0). ToA = ceil_ms((preamble + 4.25 + payload_symbols) × Tss). PL включает 12 bytes radio header; ACK занимает 14 bytes.

Одна transaction учитывает до A configured attempts: A × (1.5Tuser + Tack + 0.116) + сумму bounded backoff/jitter + 2Tss + 0.116. Binary budget = 2 transactions + 5 s local guard (два machine slots); FT1 control/resume = 4 transactions + 5 s (END/META и обратный ответ). Idle = (max_control_replays + 1) × control + drain. Drain существующих M1 tickets = max(remaining admitted deadlines, 0) + 5 s; controller reset делает эти tickets недействительными. Cancel = один уже начатый TX watchdog + ACK + guards + 5 s, без последующих retry. Boot READY = host 15 s + 1.5ToA(1 byte self-test) + UART guard.

Это верхние сроки ожидания, не задержки: LINK_OK, RESULT, RESUME и notifications будят немедленно. ST не создаёт новых RF retry. Непрерывный посторонний RF traffic может удерживать firmware channel busy дольше модели; finite host deadline тогда даёт явный fail/unknown, а не доказанную потерю пакета. В этой ревизии не добавлен отдельный RF scheduler.

Удалены общий default 3600 s и sweep cap 3600 s. ROOT/child не имеют общего часового срока; unanswered control ограничен 3 replay, каждый child — собственным budget, глубина — 8, отсутствие прогресса — 3 завершённых цикла. Generic opaque transport без timing capability сохраняет application fallback (30 s control, 1 s resume, 10 s drain, 120 s idle); это не физическая оценка LoRa.
